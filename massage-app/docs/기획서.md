> 가칭: 콜가드 (CallGuard)
> 작성일: 2026-04-01
> 버전: v0.4

---

## 1. 앱 개요

### 1.1 컨셉
업주 전용 스마트 전화앱. 사용자 간 고객DB 공유 기능에 업장 관리(관리사, 예약, 출근부)를 결합한 올인원 앱. 안드로이드 기본 전화앱으로 설정하여 사용.

### 1.2 핵심 가치
- **고객 사전 확인** — 전화 수신 시 다른 업주들이 등록한 블랙/진상/콜폭 이력 즉시 확인
- **업무 효율화** — 통화기록 → 예약 등록 → 관리사 배정 원스톱
- **자동 홍보** — 출근부 등록 시 텔레그램 채널 자동 게시
- **기록 없는 예약** — 예약 정보는 관리사 퇴근 후 12시간 뒤 자동 완전 삭제. 장부가 남지 않음

### 1.3 타겟 사용자
- 업주 (1인 사용, 직원용 아님)
- 업종 무관 (관리자가 사용자 심사 후 승인)

### 1.4 배포 방식
- Android APK 직접 배포 (Play Store 미등록)
- 앱 실행 시 SIM 전화번호 자동 확인 (Android TelephonyManager) → 관리자가 승인한 번호만 사용 가능
- SMS 인증 불필요
- 기본 전화앱으로 설정

### 1.5 수익 모델
- 월 구독제 (관리자가 직접 결제 수금, 앱 외부에서 처리)
- 앱 실행 시 SIM 번호 확인 → 서버에서 권한 체크

## 2. 화면 구조

### 탭 구성 (하단 네비게이션 5탭)

```
[전화]  [최근기록]  [검색]  [업장관리]  [설정]
```

---

### 2.1 탭 1: 전화 (기본 다이얼러)

앱을 안드로이드 기본 전화앱으로 설정하여 모든 수신/발신 전화를 처리.

#### 수신 전화 화면
- 발신자 번호 → 서버 DB 실시간 조회
- 매칭 시 수신 화면에 표시:
  - 고객 이름 (등록된 경우)
  - 태그: `블랙`, `진상`, `콜폭`, `VIP`, `단골` 등
  - 등록 업소 수: "3개 업소에서 등록"
  - 최근 메모 미리보기
- 미등록 번호: "미등록 번호" 표시
- 오프라인 시: "DB 조회 불가" 표시 (전화 수발신은 정상 동작)

#### 다이얼 패드
- 직접 번호 입력 발신
- 번호 입력 중 고객DB 매칭 시 태그 표시

---

### 2.2 탭 2: 최근기록

#### 통화 기록 목록
- 기본 전화앱과 동일한 통화 기록 (시간/번호/수발신)
- 각 번호 옆에 고객 태그 아이콘 표시 (블랙: 빨강, 진상: 주황, VIP: 금색 등)
- 미등록 번호는 태그 없음

#### 번호 탭 시 → 상세 화면
- 고객 정보 (등록된 경우)
- **[예약 등록]** 버튼 → 예약 등록 플로우:
  1. 관리사 선택 (현재 가용한 관리사만 표시)
  2. 시간 선택
  3. 코스 선택
  4. 메모 (선택)
  5. 확인
- **[정보 등록]** 버튼 → 고객DB에 신규 등록 (미등록 시)
- **[차단]** 버튼

---

### 2.3 탭 3: 검색 (고객DB)

#### 상단 구성
- **검색바** — 전화번호 직접 입력 → 고객DB + 최근 통화기록 동시 검색
- **[추가] 버튼** — 최근 통화기록 목록 표시 → 번호 선택 → 바로 고객 등록/메모 화면 진입

#### 검색 결과
- 고객DB 매칭 결과 (태그/메모 포함)
- 최근 통화기록 매칭 결과 (미등록 번호도 표시)
- 태그별 필터 (블랙/진상/콜폭/VIP/타업소/타업소직원)

#### [추가] 버튼 플로우
1. [추가] 탭 → 최근 통화기록 목록 표시
2. 번호 선택
3. 고객 등록/메모 화면으로 이동 (번호 자동 입력)
4. 태그 선택 + 메모 입력 → 저장

#### 고객 상세
- 전화번호
- 이름 (선택)
- 태그 목록 (복수 선택 가능)
- 메모 목록:
  - **내가 작성한 메모** (수정/삭제 가능)
  - **다른 업주가 작성한 메모** (읽기만, 작성자 업소명 표시)
- 등록 업소 수
- 최초 등록일 / 최근 업데이트

#### 고객 등록 (미등록 번호일 때)
- 전화번호 (필수, [추가]에서 진입 시 자동 입력)
- 이름 (선택)
- 태그 선택
- 메모 입력

---

### 2.4 탭 4: 업장관리

#### 내 업장 정보
- 업소명
- 전화번호
- 코스/가격표 관리 (추가/수정/삭제)
  - 코스명, 시간(분), 금액

#### 관리사 관리
- 관리사 목록
  - 사진 (원형 프로필)
  - 이름
  - 상태: `출근` / `퇴근` / `휴무` / `시술중`
  - 현재 예약 수
- 관리사 등록/수정
  - 사진 업로드
  - 이름
  - 소개 문구 (텔레그램 홍보용)
- 출근/퇴근 체크
  - 관리사별 토글 버튼 (출근 ↔ 퇴근)
  - 출근 시간 자동 기록

#### 당일 예약 현황
- 관리사별 예약 목록
- 시간대별 스케줄 표시
- 빈 시간대 = 예약 가능
- 시술중 상태 자동 반영
- 예약 상태: `예약` → `시술중` → `완료`
- 블랙 처리 시 → 고객DB에 블랙 태그 자동 추가

#### 업무 데이터 보안 정책
- **예약/출퇴근 데이터는 서버에 저장하지 않음 (메모리 Only)**
- 앱 실행 중에만 RAM에 유지
- 앱 백그라운드 유지 시 데이터 보존 (flutter_background_service)
- 앱 완전 종료 시 자동 소멸 — 포렌식 복구 불가
- 퇴근 버튼 클릭 시 해당 관리사 데이터 즉시 메모리 삭제
- 업무에 관한 기록은 어디에도 남지 않음

#### 텔레그램 출근부 자동 게시
- 출근 등록 완료 후 **[출근부 전송]** 버튼
- 메시지 형식:
  ```
  🏠 [업소명] 오늘의 출근부

  ✅ 김OO 관리사 (10:00~)
  ✅ 이OO 관리사 (11:00~)
  ✅ 박OO 관리사 (10:00~)

  📞 예약문의: 010-XXXX-XXXX
  ```
- 관리사 사진 포함 옵션

---

### 2.5 탭 5: 설정

#### 텔레그램 연동
- 업소별 개별 봇 사용 (관리자가 봇 토큰 입력)
- 채널 ID 입력
- 테스트 전송
- 자동 전송 시간 설정 (선택)

#### 알림 설정
- 예약 리마인드 알림
- 블랙 고객 경고 알림

#### 계정
- 내 전화번호 (인증용, 변경 불가)
- 구독 상태 표시
- 앱 버전 / 업데이트 확인

## 3. 데이터베이스 설계

### 3.1 테이블 구조

#### users (사용자/업주)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | UUID | PK |
| phone_number | VARCHAR(20) | 인증용 폰번호 (unique) |
| shop_name | VARCHAR(100) | 업소명 |
| shop_phone | VARCHAR(20) | 업소 전화번호 |
| telegram_channel_id | VARCHAR(50) | 텔레그램 채널 ID |
| telegram_bot_token | VARCHAR(100) | 봇 토큰 |
| is_active | BOOLEAN | 구독 활성 상태 |
| subscription_expires | DATETIME | 구독 만료일 |
| created_at | DATETIME | 가입일 |

#### customers (공유 고객DB)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | UUID | PK |
| phone_number | VARCHAR(20) | 고객 전화번호 (unique) |
| name | VARCHAR(50) | 이름 (선택) |
| registered_by_count | INT | 등록 업소 수 (캐시) |
| created_at | DATETIME | 최초 등록일 |

#### customer_entries (업주별 고객 메모)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | UUID | PK |
| customer_id | FK → customers | 고객 |
| user_id | FK → users | 작성 업주 |
| tags | JSON | 이 업주가 부여한 태그 ["블랙","진상","콜폭","VIP","타업소","타업소직원"] |
| memo | TEXT | 메모 |
| black_count | INT | 블랙 횟수 (이 업소 기준) |
| created_at | DATETIME | 작성일 |
| updated_at | DATETIME | 수정일 |

#### therapists (관리사)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | UUID | PK |
| user_id | FK → users | 소속 업소 |
| name | VARCHAR(50) | 이름 |
| photo_url | TEXT | 프로필 사진 |
| intro | TEXT | 소개 (홍보용) |
| is_active | BOOLEAN | 재직 상태 |
| sort_order | INT | 표시 순서 |
| created_at | DATETIME | 등록일 |

#### ~~attendance~~ — 테이블 없음 (메모리 Only로 변경)
> 출퇴근 데이터는 DB에 저장하지 않음. 하단 메모리 Only 섹션 참조.

#### reservations — 메모리 Only (서버/디스크 미저장)
> 예약 데이터는 **서버에 저장하지 않음**. 앱 RAM에서만 운영.
> 앱 완전 종료 시 자동 소멸. 포렌식 복구 불가.
> 금액 정보 미저장.

앱 메모리 내 예약 데이터 구조:
- customer_phone — 고객 번호
- therapist_id — 담당 관리사
- start_time — 시작 시간
- duration_min — 시술 시간 (분)
- course_name — 코스명
- status — reserved/in_progress/completed
- memo — 메모

#### attendance (출퇴근) — 메모리 Only (서버/디스크 미저장)
> 출퇴근 데이터도 예약과 동일하게 **서버에 저장하지 않음**. 앱 RAM에서만 운영.
> 퇴근 버튼 누르면 즉시 메모리에서 삭제.
> 텔레그램 출근부 전송 시에만 일시적으로 데이터 사용 후 소멸.

앱 메모리 내 출퇴근 데이터 구조:
- therapist_id — 관리사
- check_in — 출근 시간
- check_out — 퇴근 시간
- status — working / off

#### courses (코스/가격표)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | UUID | PK |
| user_id | FK → users | 업소 |
| name | VARCHAR(50) | 코스명 |
| duration_min | INT | 시간 (분) |
| price | INT | 금액 |
| is_active | BOOLEAN | 활성 |
| sort_order | INT | 표시 순서 |

## 4. API 설계

### 4.1 인증
```
POST /api/auth/verify-phone    # 폰번호 인증 요청 (SMS 코드)
POST /api/auth/confirm         # 인증 코드 확인 → JWT 발급
GET  /api/auth/me              # 내 정보 + 구독 상태
```

### 4.2 고객DB (공유)
```
GET    /api/customers/search?phone=010xxxx    # 번호 검색
GET    /api/customers/{phone}                 # 고객 상세 (내 메모 + 타인 메모)
POST   /api/customers/                        # 고객 등록
PATCH  /api/customers/{phone}/entry           # 내 메모/태그 수정
GET    /api/customers/lookup/{phone}          # 수신 전화 시 빠른 조회 (간략 응답)
```

### 4.3 업장 관리
```
GET    /api/shop/                       # 내 업장 정보
PATCH  /api/shop/                       # 업장 정보 수정

GET    /api/shop/courses                # 코스 목록
POST   /api/shop/courses                # 코스 추가
PATCH  /api/shop/courses/{id}           # 코스 수정
DELETE /api/shop/courses/{id}           # 코스 삭제

GET    /api/therapists/                 # 관리사 목록
POST   /api/therapists/                 # 관리사 등록
PATCH  /api/therapists/{id}             # 수정
DELETE /api/therapists/{id}             # 삭제
POST   /api/therapists/{id}/check-in    # 출근
POST   /api/therapists/{id}/check-out   # 퇴근 → 12시간 후 예약 자동 삭제 예약
GET    /api/therapists/available?date=   # 현재 가용 관리사
```

### 4.4 예약 — API 없음 (앱 로컬 메모리에서 처리)
> 예약/출퇴근 데이터는 서버를 거치지 않음.
> 앱 내부 상태 관리로만 운영 (메모리 Only).

### 4.5 텔레그램 연동
```
POST   /api/telegram/send-attendance    # 출근부 수동 전송
POST   /api/telegram/test               # 테스트 메시지
PATCH  /api/telegram/settings           # 채널/봇 설정
```

### 4.6 관리자 (나)
```
GET    /api/admin/users                      # 전체 사용자 목록
POST   /api/admin/users/{phone}/activate     # 구독 활성화
POST   /api/admin/users/{phone}/deactivate   # 구독 해제
GET    /api/admin/stats                      # 전체 통계
```

## 5. 기술 스택

| 구분 | 기술 | 이유 |
|------|------|------|
| 앱 | Flutter (Dart) | 네이티브 전화 기능 지원, 크로스플랫폼 |
| 백엔드 | FastAPI (Python) | 경량, 비동기, 빠른 개발 |
| DB | PostgreSQL | 관계형, 검색 성능 |
| 배포 | 해외 VPS (Hetzner/Vultr) | 익명 운영, 암호화폐 결제 가능 |
| 이미지 | Cloudinary | 관리사 프로필 사진 |
| 텔레그램 | python-telegram-bot | 채널 자동 포스팅 |
| 인증 | SMS 인증 + JWT | 폰번호 기반 |

### Flutter 주요 패키지
- `flutter_background_service` — 백그라운드 통화 감지
- `call_e_log` — 통화 기록 접근
- `permission_handler` — 시스템 권한 관리
- `flutter_local_notifications` — 로컬 알림
- `dio` — HTTP API 호출
- `hive_ce` — 로컬 캐시 (오프라인 시 "DB 조회 불가" 표시용)
- `get_it` — 의존성 주입
- `proximity_sensor` — 통화 중 화면 꺼짐
- `image_picker` — 관리사 사진 촬영/선택

### Phase 2: 전화 기능 (2~3주)

## 7. 보안 및 개인정보 보호

### 7.1 데이터 보호
- **예약/출퇴근 = 메모리 Only** — 서버/디스크에 저장하지 않음. 앱 RAM에서만 운영
- **앱 종료 = 데이터 소멸** — 전원 꺼지면 RAM 소멸, 포렌식으로도 복구 불가
- **퇴근 시 즉시 삭제** — 퇴근 버튼 누르면 해당 관리사 데이터 메모리에서 즉시 제거
- **금액 정보 미저장** — 예약에 가격 필드 없음, 장부 기록 없음
- **서버에 업무 기록 없음** — 서버가 털려도 예약/출퇴근 데이터 자체가 존재하지 않음
- 고객 전화번호: 서버에 해시 저장 또는 AES-256 암호화
- 메모 공유: 작성 업소명만 표시, 업주 개인정보 비공개
- 차단 번호: 업주별 개별 관리 (공유 안 함)
- 서버 로그: 접속 IP/민감 정보 로그 최소화

### 7.2 앱 보안 (APK 보호)
- **코드 난독화** — Flutter 빌드 시 `--obfuscate --split-debug-info` 적용 (디컴파일 방지)
- **SSL Pinning** — 서버 인증서 고정, 중간자 공격(MITM) 차단
- **루팅 감지** — 루팅된 기기에서 실행 차단
- **APK 위변조 감지** — 서명 검증, 리패키징 방지
- **API 키 하드코딩 금지** — 민감 데이터는 서버에서만 관리

### 7.3 서버 보안
- **API 통신**: HTTPS 필수 (TLS 1.3)
- **JWT 토큰**: 30일 만료 + refresh
- **Rate Limiting**: API 요청 제한 (무차별 크롤링 차단)
- **관리자 승인**: 무분별한 가입 방지
- **DB 접근**: 서버 내부에서만 허용 (외부 포트 차단)
- **SSH**: 키 인증만 허용 (비밀번호 로그인 비활성화)
- **방화벽**: 필요 포트만 개방 (80, 443)
- **자동 백업**: 암호화된 DB 백업

### 7.4 서버 익명 운영
- **호스팅**: 해외 VPS (암호화폐 결제 가능한 서비스)
- **도메인**: 프라이버시 보호 등록 (Whois Guard) + Cloudflare로 실제 서버 IP 숨김
- **코드 저장소**: 비공개 저장소, 커밋에 실명/이메일 노출 금지
- **연락처**: 별도 전화번호 + 별도 텔레그램 계정 + 익명 이메일 (ProtonMail)
- **APK 서명**: 서명 키에 개인정보 포함하지 않음
- **텔레그램 봇 토큰**: 서버에서만 사용 (앱에 노출 안 함)
